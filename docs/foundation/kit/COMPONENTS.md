# COMPONENTS — the genericised substance (the founding Lead reads this)

Everything a same-scope AI/content/monetization SaaS multi-agent team needs, pre-configured, with project-specifics as `[FILL]` (resolved from Phase 1–2). Placeholders: `<Project>` `<slug>` `<repo>` `<dir>` `<prefix>` `<lead>` `<trailer>`.

## 1 · Load-bearing principles (seed `dev-lessons-learned.md` with these)
1. **All durable state lives in the repo**, never in a session's context → every agent is disposable/refreshable.
2. **One session per clone, one clone per session** (shared worktrees corrupt git state).
3. **Independent review beats self-review — builder ≠ judge.** Builders build; separate oversight reviews, reporting to the Director. No seat certifies its own work — extended to a mechanical rule in §10.
4. **Spec-complete-before-build** for high-invariant work (transactions, crash-safety, gate-semantics, auth/tenant-iso, migrations, any money-truth surface): lock the complete invariant checklist (implementer+QA) BEFORE building.
5. **Armed assertions / no vacuous green** — every gate leg must FAIL on the exact defect it guards, proven by a planted negative control. A gate that cannot fail manufactures false confidence and is worse than no gate.
6. **Coverage is earned with evidence, never inference** — a rule not yet written is a **gap**, not an assumed pass (the same rule that governs an `UNMEASURED` axis: absence of measurement is not a passing measurement).
7. **Disjoint-file lanes + hot-file append protocol** for the few shared coordination files.
8. **Govern the cost that's real** — subscription headroom vs billed per-use spend; cap + attribute whichever is real. Govern real per-**unit** COGS, not the headline rate (a model swap can be rate-neutral yet raise per-call COGS via a different tokenizer); the standing infra floor (DB/CI/hosting) is part of the cost model. **"Cost" means money — the agent team's labour is already paid for; never price a recommendation in effort/schedule/seats, only in dollars + correctness-risk.** *(But the Director's own time is a real, binding cost — never dismiss it.)*
9. **Pre-authorize the routine; reserve decisions for the meaningful.**
10. **Build against the real, current structure** — validate dirs/ports right before authoring; don't build against a moving/under-specified target.
11. **Verify, don't attest — including your own compilation.** A synthesiser's own summary is the least-audited artifact in the system; re-derive a claim before relaying it, and have a *different* seat audit any synthesis that feeds a decision.
12. **The map is not the territory: same tier ≠ same reason.** Agreement on an answer while disagreeing on *why* is not agreement — it is a coincidence that hides a real divergence. Grade and gate on the reason, not just the verdict (§11).
13. **Completeness by default — nothing under the rug.** Anything put before a decision-maker shows the COMPLETE picture — nothing dropped, deferred out of view, footnoted, or averaged into invisibility. **Deferred ≠ excluded** (phasing the *build* is legitimate; phasing the *decision picture* is a distortion — deferred parts stay in at full weight, with deferral shown as a schedule fact beside the full figure). Every number/claim flagged **measured / estimated / unmeasured**. Dropped items surface **with their reason**. Presented **proactively** — if the decision-maker had to probe for the missing piece, the presentation already failed. Accountability runs both ways: surface the decision-maker's own framing gaps too.
14. **A consistency check passes a uniformly-wrong fact every time — only a source citation catches it.** Copies that agree prove nothing; a fabricated fact survives across every document that repeats it. External facts carry a **source + read-date** or they are a GAP (not an assumed pass), re-verified at point of use; and cite the **revision you observed against** — editing text that isn't there produces a plausible diff, not an error.
15. **Residuals are declared, classified and owned — and most are tasks in disguise.** The forcing test: *what would it take to check this?* If the answer is a lookup, it is **not a residual — it is a task you have not done.** Genuine residuals split cleanly: **facts have sources** (unverified-until-cited), **ongoing behaviours have owners** (a continuing promise a citation cannot close). Every residual is a promise you *chose* to make — eliminable only by promising less.

## 2 · Roster — the MAXIMAL-SUPERSET archetype library + per-role charter template
**Philosophy:** enumerate **every distinct role** the *largest / most-complex* version of this program would need, then **scale back** to the subset the project requires. Do **not** merge/fold/drop roles for leanness up front — that buries accountability and forces you to *discover* a missing seat mid-build (costly rework). Define the superset; the Director picks the subset (a solo/early product may run ~8–12 core seats with the Lead wearing several oversight hats; add a seat the moment its surface appears). Oversight is **independent of builders + reports to the Director**; pod ICs report to their pod lead.

**Core governance/build spine (always on, any project):** Program Lead · Principal Architect (on-demand) · QA · Governance & Audit · SecOps · at least one Backend + one Frontend builder · DevOps. **These never come off.** Everything below is an **opt-in menu** enabled per project type.

## 3 · Lane cut (standard 4-lane; disjoint by file — map to the REAL tree in Phase 2/3)
- **Lane 1 · transport/API** → BE-API: the server app (HTTP dispatcher, request-context/tenant resolver, auth, `{ok,data|error}` envelope, job spine, credential threading).
- **Lane 2 · domain-logic + DB** → BE-Data: the framework-free domain modules + DB adapter + migration files. Owns any **money-truth chokepoint** (the single metered path for billed calls).
- **Lane 3 · frontend/SPA** → FE-Web: the client (router, shell, API-client facade, upload/download, screens). No business logic in components.
- **Lane 4 · build/env** → DevOps: build config, local DB, gate harness, CI, RLS/policy lint, drift guard, secrets/keys, **the oracle-leg runner**.
- **Hot files** (shared): the API-contract file, the board, the migration folder, the append-only log → per-lane labeled append blocks · keep-both on rebase · **Lead allocates sequential IDs**.

## 4 · Protocols (verbatim into the charter §4)
1. `git pull --rebase` before editing AND before pushing; small commits; **targeted `git add <paths>` (never -A)**. High-concurrency repos: expect rejected pushes → **rebase-first, then retry**; stash any perennial always-dirty file before pulling + pop after.
2. Green-per-commit once the gate exists.
3. Net-new scope → the decisions-log **before** building it. **A decision is NOT closed until it is PROPAGATED** — the downstream docs the bound parties actually read (briefs, specs, the design doc, ledgers) are **named in the decision row** and updated **in the same commit**, or the row states `→ PROPAGATION: none` + why. *The log is where a decision is proven, not where it is obeyed.*
4. Commit trailer `<trailer>`; never commit secrets; **no literal model IDs** in code/docs — the ONE exception is the kit's §2 model-mapping line (the Director-locked Architect/build assignment), the single sanctioned home for model names.
5. One session per clone; cross-session via [messaging] + the repo.
6. Context self-management (§8).
7. Every wave is bracketed: a **Wave-Entry Gate before** (Lead authors the plan → oversight reviews → **Director GO**; the Lead never self-dispatches) + a **QA phase-exit sign-off after**.
8. **`adr_reference` on every build task** — an approved ADR ID or `BYPASS`+justification. Never BYPASS-eligible: shared contracts · schema · new subsystems · any auth/security code · the first instance of a repeating pattern.
9. **No background/async subagents.** All research + background work runs in **visible team-role sessions** the Director can watch; every role agent completes its own task and does not spawn subagents, so a stall is visible.
10. **UI-mockup gate** — any task with UI elements goes to the Design Lead for a mockup + **Director approval** before it reaches the Architect (only if the product is CX-heavy).
11. **Assign-by-message + report-on-completion + surface-blockers-mid-task, `[Via messenger]`** — the Lead **always assigns a task to a named seat by message** (`[Via messenger]`), never by any other channel. The assigned seat **reports back to the Lead directly on completion** (cross-session message + the repo artifact) — **AND messages the Lead the MOMENT it hits a blocking question, ambiguity, or issue mid-task; it never sits on a blocker, and never guesses past one.** It communicates DIRECTLY with other named seats as the assignment requires. The receiving seat must be verified ACTIVE in its own context window before dispatch (session IDs rotate). No silent finishes; the Director is never the middleman.
12. **"Cost" means money** (principle §1.8) — bound into the charter as a standing directive.
13. **THE TWO-DOCUMENT RULE.** The design lives in **ONE canonical design doc** — one clean read, the single source, statements numbered `<x.y>`, open items marked inline. Its history is **ONE append-only log**. **(a)** On spawn, read the canonical doc FIRST; where anything disagrees with it, it wins. **(b)** Reference design by its `<x.y>` id, never by re-describing it in prose (prose descriptions are what drift). **(c) ONLY THE LEAD EDITS THE CANONICAL DOC; every other seat APPENDS to the log** and the Lead absorbs it. **(d)** Never re-derive design from a role log, a brief, or an archived file — those are history; the canonical doc is truth. **(e)** Build-time numbers (band tables, thresholds, ADR structure) live in a few named single-owned annexes; everything needed to *understand and approve* the design is in the canonical doc itself.
14. **THE ORACLE / ESCALATE-BOUNDARY RULE** — see §10 (the governance layer). Binding on every seat.
15. **THE DELIVERY PIPELINE — the decision-maker DECIDES, never debugs.** Nothing reaches the decision-maker until it is **COMPLETE, GROUNDED, RECONCILED, VERIFIED.** Five gates, the decision-maker only at the last: **① SCOPE** — one axis per item; do not conflate concerns. **② GROUND** — complete (principle §1.13 — nothing under the rug) + every number flagged measured/estimated/unmeasured; owned by the producing seat. **③ RECONCILE** — checked against the full decision set by a **second seat / GA — never the author** (the decision is re-derived, not re-asserted). **④ VERIFY-AT-SOURCE** — the Lead reads the **citations, not the claims** (a synthesiser's summary is the least-audited artifact, §1.11). **⑤ DECIDE** — the decision-maker. 🔴 **The rule that makes it real: if the decision-maker catches an error instead of making a decision, the item FAILED an earlier gate and goes back — it is never patched in front of them.** This is the standing default for anything reaching the Director; it generalises §9.B8 + §11 (which supply the review mechanics) into a pipeline every artifact runs. 🔴 **ONE CHANNEL, ONE REPORT.** A seat reports to the **Lead**, never the Director, on any finding another seat also holds; the Lead **holds, consolidates, reconciles the seats against each other, and presents ONCE** — and **one report per piece of work, at completion**, not at design or per leg (sole exception: a genuine BLOCKER). *Convergence the decision-maker must watch is indistinguishable from churn they must arbitrate — several seats each reporting concisely and in parallel IS the failure, not any one message; and the Lead is the proximate cause when it relays each finding onward as it arrives instead of consolidating.*

16. 🔴 **NOTHING LEAVES A SEAT WITHOUT THE ARTIFACT THAT MAKES IT CHECKABLE.** A COUNT carries its ROWS · a NUMBER its SOURCE · a DECISION its DOCUMENTS · a DESIGN STATEMENT its id. *The assertions that most need checking are exactly the ones nobody is motivated to check — the one that AGREES with you survives because it agrees.* **Store the FILTER, not the count** (a count is a cached computation that decays; a filter re-derives every read). **Carry a qualified figure as its expression** (`min(2%, $1)`), never its rounded worst case — the rule binds at every step that **USES** a figure, not only the step that STATES it (a record can stay correct while the reasoning three lines down goes wrong). **A constraint a vendor VOLUNTEERS outweighs a capability it ADVERTISES** — a documented limit is what they had to build around; a marketing claim is what they want you to believe. And it binds what a seat **ACCEPTS**, not only what it produces: when a statement and its governing artifact disagree, **the governing artifact WINS — establish which one governs BEFORE resolving the disagreement** (a terse, convenient, or question-resolving source is not thereby authoritative; a wrong answer folded into a seat's artifact acquires that seat's credibility and travels further because it was dressed).
17. 🔴 **RECURRING VALIDATION — critical changes get an independent second set of eyes; the Lead's own output is not exempt.** A **CRITICAL** change (an engine rule/number · a ruled decision that propagates · a cross-document invariant · a spend-moving change) gets BOTH the author's verify-at-source (protocol 15 gate ④) AND an **independent, different-agent validation** BEFORE it is presented as reconciled/certified — GA for governance/consistency, the eval seat for scoring-content. A **ROUTINE** change (doc hygiene · absorbing an already-ruled item · a log entry) gets **self-check only** — the tier is load-bearing: validating every edit recreates the exact cross-channel volume protocol 15 exists to prevent. No new role — it points the existing builder ≠ judge machinery (§10/§11) at the one author it was never aimed at: **the seat that reconciles everyone else was the one nobody reconciled.** The validator is never the author, runs before the item is presented, and reports **as part of** the single report-at-completion — never a new channel.
18. **A decision states its SCOPE — instance or class — at the moment it is ruled.** A rule filed under one instance reads as complete and gets re-derived from scratch later; the register cannot catch it, so the ruling itself must say which it is.
19. **Superseded design is DELETED, not parked.** Do not banner it, park it, or move it to a reference file — a fully-worked superseded model is confidently written, which is exactly the shape that gets implemented. **Check what else is in a row before cutting it** (an unrelated live ruling riding inside a cut row goes with it). Normative counterpart (§5): a defect-fix to a normative doc **re-authors** the sections it touches, never patches alongside the superseded text — a document that says two contradictory things is worse than one that is simply wrong.

## 4.5 · Symbol legend (binding project-wide — one meaning per marker)
Two scales share the palette and never collide (a finding is always tagged `SEVn`; an item never is). **STATUS (items/board/ledger):** 🔴 blocking · 🟡 open · 🟢 cleared/go · ✅ done · ▶ running · ⏸ held · 🔒 locked · ⚠️ caution · `▸` = inline design markers in the canonical doc only. **SEVERITY (findings — oversight only):** 🔴 SEV1 · 🟠 SEV2 · 🟡 SEV3 · 🔵 SEV4. Both anchor 🔴 = most-urgent. **A fresh clone must read the legend, not infer it** — codify it in the charter so every seat reads colours identically.

## 5 · Governance
- **Decisions-log** — append-only, IDs `<prefix>NNN`, columns `ID · date · decision · why · decided-by`. Numbering: MAX+1 at rebase; later push renumbers on collision; keep both. **Every row carries its propagation list (protocol 3).**
- **Gate framework** — one runner (§6) asserting **exit codes, not piped tails**; checks **armed** (fail on their defect, proven by a negative control) + **exit-visible SKIP** when un-armed. Standing pre-authorization to add armed legs (log the leg + count; only a change to the *meaning* of green needs a decision).
- **Phase-gate QA sign-off** — QA re-runs the full gate on each phase HEAD *in its own clone, on exit codes*, before the next wave unblocks. No self-merge.
- **Wave-Entry Gate** — before any wave builds: the Lead authors a **Wave Plan**, oversight reviews its slice, the **Director approves GO**. → §9.B6.
- **Engineering-Quality-Bar + Build-Standards** → §9.B2/B3.
- **SEV scale** — §4.5; SEV1/2 escalate to the Director immediately.
- **The delivery pipeline (protocol 15)** — the five-gate discipline (SCOPE → GROUND → RECONCILE → VERIFY-AT-SOURCE → DECIDE) that keeps the decision-maker deciding, never debugging. **GA owns the RECONCILE gate** (cross-decision consistency — never the author); **the Lead owns VERIFY-AT-SOURCE** (reads citations, not claims). A caught error means an earlier gate failed — the item goes back, never patched in front of the decision-maker. **Its one-time backlog form:** a **contradiction & gap sweep** — one GA-led pass that surfaces ALL accumulated contradictions, ungrounded numbers and deferred-but-sold items at once, cleared deliberately in one sitting instead of discovered one probe at a time (run it whenever churn signals the backlog has grown).
- 🔴 **A4/A5 — standing pre-certification checks on ANY authored decision/band table** (scoring, dimension bands, gauges, gates — anything mapping inputs to a rule; the mechanism behind LL-51). **A4 · EXHAUSTIVE** — enumerate the input space, assert **exactly one** band/rule matches every input. **A5 · REACHABLE** — exhibit an input firing each rule; applies to **SUBSTANTIVE rules only** — an explicit terminal catch-all is a safety net, EXEMPT, and *should* be unreachable (its unreachability is evidence the table is total, not a dead rule to delete). Spec-level (no data/build needed); the author fixes, an **independent seat runs them** (builder ≠ judge). *Every first run is a sample — a proper independent re-run finds more.*
- 🔴 **A6 — a revision must DECLARE WHAT IT CHANGED.** A4 proves a table is total; it does not prove it still says what it used to. **A6a predicate-retention** — any decision variable/threshold present in the old revision and absent in the new is **named as a deliberate removal, with a reason** (a variable that silently stops being referenced is a distinction deleted, not partitioned). **A6b delta-partition** — run A4 on both revisions; split changed inputs into legitimate repairs (state the chosen value) vs. inputs well-defined before that now resolve differently (empty or explicitly justified). The real value: it converts a silent edit into a written claim a reviewer can disagree with.
- 🔴 **Normative specs are RE-AUTHORED, not patched.** A defect-fix to a normative document (scoring logic, gate spec, ADRs, schema specs) re-authors the sections it touches rather than inserting alongside the superseded text — *a reader cannot tell which half is live, and the stale half reads as authoritative to whoever finds it first.* Narrative/log documents are exempt.
- 🔴 **Recurring validation (protocol 17), governance form.** A **critical** change gets an independent, different-agent validation **before** it reaches the decision-maker as reconciled — **including LEAD-authored artifacts** (canonical-doc edits, decision rows, any synthesis), which the delivery pipeline's author-side gates never independently checked. Tiered so routine changes get self-check only. **GA owns confirming the independent validation actually ran on every critical change** (a claimed validation with no second seat is a GAP — the §10 coverage-audit discipline, turned on the process itself).

## 6 · Gate framework + default-stack commands
Single runner, ordered, exit-code-honest, declared-SKIP for un-armed. **Default stack (Node/TS · Fastify · Postgres/Supabase · React/Vite):** 1 `tsc --noEmit` · 2 build · 3 `test`/eval golden set · 4 `migrate` + RLS/policy-lint (per tenant table: policies · `WITH CHECK` · `NOT NULL owner_id` · `(owner_id,id)` index · deletion-class) · 5 transport smoke · 6 tenant-isolation (must FAIL with RLS OFF) · 7 drift guard. CI: same runner + secret-scan + dep-audit. **Add project-specific armed legs:** a **money-truth leg** where spend is billed (a call bypassing the meter FAILS); a **compliance leg** where a bright-line exists (a forbidden dependency/code-path FAILS); **the oracle legs from §10.** **Custom stack:** map each check to the stack's equivalent; keep the structure + armed-assertion rule.

## 7 · Wave templates (Phase 1 picks one)
**GREENFIELD:** W0 Scaffold (skeleton + DB day-one + gate green on empty app) → W1 Core spine (transport + request-context/tenant + auth + DB adapter + envelope/credentials + job spine + any money-truth chokepoint) → W2 Client shell → W3+ Features (per the design; disjoint-by-lane; phase-gated).
**PORT:** A0 Call-convention + DB (serialized, single-owner, freeze shared files) → A1 Transport → A2 Client SPA → A4 Build/env. Both: phase-gate between waves; parallelize only the disjoint.

## 8 · Routines (standing — write into the charter/ledger)
- **Context-refresh (wave-boundary):** sessions clone/handoff to fresh contexts; state lives in repo. **Context-handoff/spawn rule:** the outgoing agent writes its full context to `docs/roles/<role>/activity-log.md` FIRST **and pushes it; the incoming clone verifies the handoff commit is on origin before continuing** — a clean *local* tree ≠ a *fetchable* handoff.
- **Output-quality audit:** any scoring/ranking/recommending/generating feature gets a golden eval set + defensible thresholds before it exits its phase.
- **Spec-complete-before-build (§5).** **Lessons-learned register** (`docs/dev-lessons-learned.md`), fed same-day by all roles — **and harvested into the kit's `FOUNDING-LESSONS.md` + the role's lessons block at the founding hand-back.**
- **Verify-don't-attest (§5 QA):** oversight independently re-runs the gate on exit codes in its own clone; for a negative control it reproduces the failure **as the restricted role with its own minted credential** — "should fail" ≠ "proved it fails."
- **Re-verify-at-action-time:** before executing any research-derived or launch plan, run a fresh check that nothing has changed since the research — never trust stale research at execution.

## 9 · Build-phase gate components (layer these on; each independently adoptable)
> Adopt per product: **B1/B2/B3/B6/B8 near-universal; B4/B5 arm at a billed chokepoint; B7 when CX-heavy; B9 fronts every NEW-opportunity project.** **Pre-build order:** B9 → B7 → build waves; **B8** brackets every wave; **B1 (A0/A6)** brackets the architecture. Flippable until MVP-lock; ratchet-up only.

**B1 · Architecture Gates A0/A6 + `adr_reference` triple-layer enforcement.** A0 (pre-build) ADR: summary+context · approach · ownership map · API contracts · data-model · integration impact · risks · **constraints/non-negotiables (these become others' oracle legs)** · complexity tier · co-sign. A6 (post-build, pre-merge) ASR: ADR-compliance · drift log · regression check · verdict · Observations-Outside-Scope; merge only after A6. Complexity-tier the ASR depth (frontier for critical, default-model for standard). Review roster: QA always; security on auth/keys/PII; finance on chokepoint; design on scoring/generating surfaces. **B8 · The Assurance Layer (front-weighted quality — ~70% front / ~30% the dial).** Rework is born UPSTREAM. Four mechanisms, tiered by stakes: **(1) FRONT GATE** — before any nontrivial wave: a completeness check (every requirement → an acceptance criterion → a planned test; no orphans) + a **design red-team** (an independent reviewer files a written "here is where this breaks" memo BEFORE code; the dispatch decision must rebut it in writing). **(2) BACK GATE** — adversarial correctness verification on the HARDEST surfaces only (money chokepoint · auth · migrations · AI-output); the verifier is tasked to **REFUTE** (a concrete failure scenario, or "I attacked it via X/Y/Z and it held") — never a vacuous "looks good." **Default = one independent reviewer**; multi-agent fan-out is an opt-in, Director-gated escalation, never standing. **(3) CONNECTIVE TISSUE** — traceability requirement→task→test; flip-the-defect tests. **(4) COST DISCIPLINE** — tier/measure/kill; no builder at Max; drop any verify layer not paying for itself. **See §11 for the matured independent-review process this generalises.**

**B9 · The Validation Gauntlet (product Phase-0 — opportunity→viability)** *(new-opportunity projects).* Nothing designs/builds until the opportunity clears viability + a blueprint is signed. Each gate cheap relative to the next (spend least to *disprove* first); a hard Director go/no-go; the **Skeptic mounts a kill-attempt at every gate**. **8 gates:** G1 Niche & Demand → G2 Solution Hypotheses → G3 First-Pass Competition → G4 Feature Set/MVP → G5 Deep Comparative→Wedge → G6 Traction Forecast → G7 Viability/unit-economics → G8 Blueprint (**the only door into the build org**). **5 hardening rules:** Skeptic has teeth (→ Director, written kill-memo the proceed-decision rebuts) · one living Opportunity Dossier · free-first, hard paid-data unlock · label estimate confidence (wide date band until velocity calibrates) · force pivot/persevere/kill each loop (max 2, then kill). **Run as a COHORT** (seed 3–5 → free-screen G1–G3 in parallel → deep-analyze survivors together in one paid window → rank at G7 → blueprint winners into a ranked pipeline).

**B10 · Operational-Readiness & Assurance-Register governance** *(arms at the launch/operational-readiness phase; near-universal for any product that goes live).* Turns the design's standing risks and its live-operations obligations into instrumented, discoverable, audit-ready mechanisms.
- **Hazard / assurance register.** Every risk the design carries is a row: **what must be BUILT · who owns it · HOW WE KNOW IT HOLDS** — a row added the **moment a ruling names a hazard**, not at the end of a pass. 🔴 **Every row carries a TEST IDENTIFIER and the build FAILS if any row has none** — *"no test yet" is not an entry.* A not-yet-testable row goes in a **§0** naming **what would make it testable · its trigger · what must be BUILT NOW · who watches**, and its **default disposition is INSTRUMENT IT** — a judgment you cannot yet test is instrumented until it becomes observable, or is explicitly accepted-and-watched. *"We cannot test this" is not an available answer.* Standing mandate: convert every check done by **conversation** into a check the **build runs.**
- **Policies & SOPs — documented, versioned, published BEFORE go-live** (litigation/discovery readiness). Editable source → **frozen, dated PDFs, append-only** (object-locked), date-range retrievable from the operator console.
- **Engineering & change governance — an IMMUTABLE, append-only release/change log auto-emitted by CI/CD:** what shipped · tested-how · when-to-prod · who · rollback. The record is a by-product of the pipeline, not a document someone maintains.
- **Living reference docs stay in sync.** A doc with a generated companion (source-of-truth `.md` → generated `.docx`, an integrations dossier, a policy register) is regenerated **in the same commit** as any change that touches it; out-of-band (outside-the-tool) task **status lives in ONE status home**, detail in the specialist docs.

## 10 · THE ORACLE / ESCALATE-BOUNDARY GOVERNANCE (the maturation this kit adds)
> The single highest-leverage governance layer: it puts **mechanical certainty** where it is cheaply achievable and reserves **human judgment** for where it is actually needed — and it defends hard against the failure mode that ruins gated systems (a confident GREEN over something the mechanism never checked).

**The rule.** Wherever a seat's output can be checked by a **sound, cheap, auditable oracle**, it is gated by that oracle — not by human/agent review alone. A sound oracle: **(a)** rests on a **small trusted seed you can audit by eye** · **(b)** is **cheaper to check than to satisfy** (verification asymmetry) · **(c)** **fails-closed on the exact defect it guards, with a planted negative control** (no vacuous green) · **(d)** emits a **per-artifact certificate** (ack ref / stamp id / scan result / ruleset version). Where **no** sound oracle exists (taste, ambiguous law, strategy, real-world side-effects), the duty is **HUMAN and escalates** — and a confident panel may **never launder an un-oracle-able duty as certified.**

**Builder ≠ judge.** The seat **authors its rule-set**; a **different** seat **builds** the oracle; **GA audits** its coverage; **QA re-runs** on exit. No seat certifies its own work.

**🔴 The admission test for the certified column (the binding entry gate — because the boundary is itself a judgment and the pressure always runs toward over-claiming the mechanical side).** A duty may be placed in the certified/oracle column **only if a seat OTHER than the one judged can produce a reproducible NEGATIVE CONTROL** — a concrete input that *should* be rejected and *is*, one that makes the leg FAIL. **No live negative control ⇒ not oracle-able ⇒ the duty stays HUMAN and escalates.** Default is HUMAN; certified is **earned, never assumed.** The enforcing question, asked of any certified claim: ***"show me the input this green would reject."*** No answer collapses the claim to HUMAN.

**The new failure mode, explicitly GA-owned.** An oracle is only as good as its rule-set — a *missing* rule ships a green over real exposure, worse than no check. **GA (#5) owns catching that** as a **standing job**: on every rule-set change and on staleness, audit **coverage** (does the leg cover the defect class its row claims — a claimed cert with no leg is a GAP), **soundness** (does each leg have a negative control that bites), and **boundary honesty** (is any seat claiming the certified column for a duty that is really human — the admission test as an objective failure).

**The per-seat boundary table.** Founding authors `docs/gate/oracle-boundary.md` — one row per seat: *what it certifies mechanically (fail-closed) · what stays HUMAN and escalates · who authors the rule / who builds the oracle (never the seat judged).* **Every certified cell names the LEG'S ACTUAL ASSERTION, and every residue the oracle cannot soundly check is named in the HUMAN column.** The honest-row model: an ORACLE seat that still keeps its judgment call in the HUMAN column (e.g. Legal certifies a forbidden-phrase scan but keeps "is this advice?" human); the strongest-oracle model: a static import-check where planting the forbidden import makes the leg fail. Tiers: ORACLE (mechanical veto) · PARTIAL (checkable sliver + human core) · VERIFIER (audits the oracles) · HUMAN (judgment only). Legs **arm at each seat's build wave**; the duty is binding from founding.

## 10.5 · Low-friction session defaults (scaffolded into every founded repo)
The scaffolder (`scripts/new-team.ps1`) commits two files that remove most day-to-day friction for every seat, in every clone:
- **`.claude/settings.json`** — `permissions.defaultMode: "acceptEdits"` (file edits + allowlisted commands auto-approve; only unusual actions prompt) + a curated **allow** list (git/gh/npm/node/gate-runner, both Bash and PowerShell forms) + a **deny** list that keeps the brakes on the destructive class (`git push --force`, `git reset --hard`, `git clean`, recursive deletes) even in permissive modes. **Full-auto (`bypassPermissions`) is deliberately NOT the committed default** — it removes the last brake; a seat that warrants it gets it **per-seat, by the Director** (the session mode toggle, or that clone's `.claude/settings.local.json`, which is gitignored). **A governed Lead may be REFUSED write access to this active permissions file by the harness (LL-70)** — in that case ship it as `docs/foundation/settings.json.template` + a Director "copy into `.claude/settings.json`" step; the Director placing it is consistent with full-auto being a per-seat Director act anyway.

## 11 · The matured independent-review process (generalises B8)
For a whole-design review or a high-stakes correctness question, the discipline that made "all perspectives, complete and accurate" a mechanism rather than a hope:
- **Blind, independent lenses.** Each reviewer takes ONE lens over the WHOLE artifact, blind-first (cite the exact `<x.y>`/number, trace the calculation, **list what was NOT covered**), before reading any other reviewer.
- **A verified synthesis — then audit the synthesiser.** The Lead compiles, verifying (not attesting to) each finding — then a *different* seat (GA) **audits the Lead's synthesis** against the source lenses. *(In practice the synthesis carried multiple errors the audit caught, including an inverted direction and a dropped hard requirement — the synthesiser's own summary is the least-audited artifact; never let it be the last word.)*
- **The builder answers, never grades.** The seat that built the thing under review responds to findings; a different seat judges.
- **Pre-registration.** Before a scored run, write down (write-once) what you expect to see and where — so a confirmed prediction is a prediction, not a post-hoc story, and a surprise is visibly a surprise.
- **🔴 Catch-matching, not tier-matching.** When grading an engine/answer against ground truth, agreement on the *verdict* while disagreeing on the *reason* is **coincidental agreement**, not success — grade on whether the named reason matches, or a right-tier/wrong-reason fix passes clean and hides a real defect.
- **Ground truth is a domain expert, blind, write-once.** For a correctness question no internal check can close, the strongest close is a domain expert (often the Director) labelling blind against a rubric agreed *first*, recorded write-once, with a genuinely independent second classifier (a *different* model) — never the builder grading itself, never the same session's two modes (an optimistic ceiling).
- **Freeze before you measure.** To measure "the thing we ship," freeze the ruleset at one pinned commit; a moving target makes the seal meaningless. The freeze lifts for the post-measurement recalibration it was protecting.
