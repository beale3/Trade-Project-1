# FOUNDING-LESSONS — the self-improvement register (v2 line: LL-1 … LL-71)

Every founding appends an entry (at least a "nothing to add" line — the step is never silently skipped). A real lesson becomes a fix folded into the kit **and the relevant `roles/` lessons block**, plus a `KIT-VERSION.md` bump. Format: *the anti-pattern (what actually happened, genericised) · the guard · where it is folded.*

This file is the kit's error-reduction engine. Two sources feed it: **foundings** (what the kit missed while founding a team) and **live-cycle harvests** (what a running team's documented failures teach — audits, decisions-logs, review records). LL-1…LL-24 are the inherited v1 line; LL-25…LL-55 are the first live-cycle harvest, from a team that ran a complete design → independent review → build-governance → ground-truth-calibration cycle.

## §A · The inherited line (v1 kit, four foundings) — LL-1 … LL-24

- **LL-1 · Validate ports/directories against the LIVE repo immediately before authoring.** Local ports were reconfigured mid-founding; authoring on the earlier values would have baked wrong ports into the charter, gate commands, and every role script. → *FOUNDATION-METHOD Phase 2 + SCRIPT-1 Step 3.*
- **LL-2 · The receiving Lead owns commits in its clone.** A second session doing `git add`/`commit` in a tree another live session owns risks corruption. Author staged/uncommitted and route the commit. → *FOUNDATION-METHOD Phase 4 + SCRIPT-2.*
- **LL-3 · Product-name placeholder hygiene.** One unambiguous token; keep the product name distinct from infrastructure identifiers (repo path, decision prefix, npm scope) so a rebrand is one clean find-replace; a blanket replace also hits sentences that *refer to* the token. → *FOUNDATION-METHOD Phase 3.*
- **LL-4 · Isolation = reuse methodology, not files.** The kit is project-agnostic process; copying it across projects violates no isolation rule. State that in each isolation banner. → *INHERITANCE-AND-MIRROR guardrails.*
- **LL-5 · Cost model drives FinOps scope.** Billed per-use vs subscription-headroom decides whether FinOps governs real dollars from day one (fail-closed COGS governor at the chokepoint). → *SCRIPT-1 Step 2.9 + COMPONENTS §1.8/§9.B4.*
- **LL-6 · Confirm cosmetic-but-embedded defaults before the first commit.** The trailer and decision prefix are baked into every file; changing them later is a multi-file pass. → *SCRIPT-1 Step 2.3.*
- **LL-7 · Tailor the roster to the product.** Actively look for the project-specific seats the standard roster misses (content/curriculum, legal, data/ML). → *COMPONENTS §2.*
- **LL-8 · Bracket every wave.** A Wave-Entry Gate (plan → oversight review → Director GO) in front of QA's phase-exit sign-off behind. → *COMPONENTS §9.B6.*
- **LL-9 · An idle lane re-syncs before it builds (dispatch-freshness).** A dormant lane pulls + re-reads the charter/decisions/its ADR before writing — the world moved under it. → *COMPONENTS §9.B6.*
- **LL-10 · Verify, don't attest — run it, don't read it — and flip the defect.** Oversight independently re-runs the gate on exit codes in its own clone; a negative control is reproduced **as the restricted role with its own minted credential**. "It should fail" ≠ "I proved it fails." → *COMPONENTS §5/§8.*
- **LL-11 · Oversight folds Definition-of-Done sharpening conditions BEFORE the build GO.** The pre-build review returns concrete DoD conditions folded into acceptance criteria before dispatch. → *COMPONENTS §9.B6.*
- **LL-12 · The build-dispatch flow is a fixed pipeline.** ADR → tasks stamped with `adr_reference` + acceptance criteria → oversight folds DoD → Director GO → ONE wave dispatched → QA phase-exit → later waves gate behind it → post-build A6. → *COMPONENTS §9.B1/B6.*
- **LL-13 · Git is high-concurrency; rebase-first is mandatory.** Expect rejected pushes → rebase, retry; stash perennial-dirty files around pulls; targeted `git add`, never `-A`. → *COMPONENTS §4.1.*
- **LL-14 · A context-save must land on origin before the fresh session resumes.** The outgoing agent writes its activity-log AND pushes; the incoming clone verifies the commit is on origin. A clean local tree ≠ a fetchable handoff. → *COMPONENTS §8.*
- **LL-15 · Rate-neutral ≠ per-unit-COGS-neutral (the tokenizer trap) + the ops floor is real.** Govern real per-unit COGS, not the headline rate; arm a $/day self-tally auto-kill; the infra floor is part of the cost model. → *COMPONENTS §9.B4 + §1.8.*
- **LL-16 · A team can structurally MIRROR another — structure crosses, content never.** Roster/gates/protocols are methodology; product, brand, decisions, design language never cross. → *FOUNDATION-METHOD Phase 1 + INHERITANCE-AND-MIRROR.*
- **LL-17 · Define the maximal-superset roster, then scale back.** Never merge/fold seats for leanness up front — that buries accountability and forces discovering a missing seat mid-build. → *COMPONENTS §2.*
- **LL-18 · Effort is a depth ceiling, not a quality dial; tier by stakes.** Max for the Architect only; xhigh for the deepest seats; High the default; max-for-all is the config to avoid. → *COMPONENTS §2.*
- **LL-19 · Front-weight quality — rework is born upstream.** The biggest win is a design red-team + completeness check BEFORE code (~70/30 front-vs-dial); a deeper-thinking builder can still be confidently wrong. → *COMPONENTS §9.B8.*
- **LL-20 · Gate the opportunity before you build it.** A cheap-disproof-first viability gauntlet fronts every new project; free signals first, paid data only for survivors. → *COMPONENTS §9.B9.*
- **LL-21 · Adversarial verification needs teeth — and is single-reviewer by default.** A verifier produces a concrete failure scenario or "attacked via X/Y/Z, held" — never a vacuous pass; multi-agent fan-out is a Director-gated escalation, never standing. → *COMPONENTS §9.B8.*
- **LL-22 · Run the Gauntlet as a COHORT → a ranked pipeline.** Seed 3–5, free-screen all, deep-analyze the survivors in one shared paid window, rank, blueprint winners. → *COMPONENTS §9.B9.*
- **LL-23 · Greenfield + an empty remote → write-then-init-then-push; never clone the empty remote.** Author into the clone dir, then git once at the end; write to the clone path explicitly — don't assume cwd. → *FOUNDATION-METHOD Phase 4 + SCRIPT-1 Step 4.*
- **LL-24 · The Director may DEFER judgment-call config; never block on it.** Record "DIRECTOR-PENDING + recommended default" and scaffold against the default. → *FOUNDATION-METHOD Phase 1 + SCRIPT-1 Step 2.*

## §B · The live-cycle harvest — LL-25 … LL-55
*One team's complete governance cycle, its failures documented in audits, decisions-log entries and review records — each genericised to an anti-pattern any team will hit.*

### Decisions & propagation

- **LL-25 · A recorded decision is not an obeyed decision — propagation IS the decision.** A governance audit found six of eight findings were rulings recorded correctly in the log **and never propagated** to the documents the bound seats actually read — including one that left a live seat briefed to build five modules a ruling had deferred. *Guard:* the downstream documents are **named in the decision row and updated in the same commit**, or the row states `→ PROPAGATION: none` + why. The log is where a decision is proven, not where it is obeyed. → *COMPONENTS §4.3; roles/lead + roles/ga.*
- **LL-26 · A propagated ruling can vanish in a rebase — and stay invisible.** A ruling disappeared during a rebase conflict-resolution; the decision row still named the target document, so everything *looked* propagated. *Guard:* after any rebase touching a file you propagated into, **re-read the propagated text before pushing.** → *COMPONENTS §4.1 discipline; roles/lead.*
- **LL-27 · Registers go stale silently, and serialization hides it.** A decision-number register sat stale for 112 consecutive decisions; nothing collided **only because seats happened to be serialized** — the register wasn't working, it was unexercised. *Guard:* update the register in the same commit as the thing it registers; treat "it never collided" as luck, not evidence. → *COMPONENTS §5; roles/lead.*
- **LL-28 · Save a revert net BEFORE a governance change, not after.** Big rule-changes (a new gating layer, a charter amendment) were made safely revertible by capturing a tag + backups + a documented one-command undo *first*. *Guard:* before any governance/structural change, record the revert path in the same commit that makes the change. → *COMPONENTS §5; roles/lead.*
- **LL-29 · Batch slow external approvals — discover the FULL request set before the one submission.** An external verification (weeks-long, out of our control) nearly ran twice because an additional scope surfaced after the first submission was configured. *Guard:* before any slow third-party approval, sweep the design for every scope/permission it will ever need in this phase and submit once. → *roles/secops + roles/architect.*

### The canonical-design discipline

- **LL-30 · Design scattered across many documents WILL drift — reassembly is the failure mode.** Reassembling design state from many files by hand dropped, misread and duplicated items repeatedly within a single day. *Guard:* the **two-document rule** — ONE canonical design doc (numbered statements; only the Lead edits it) + ONE append-only log (every other seat appends; the Lead absorbs). Reference design by its number, never by re-describing it — prose descriptions are what drift. → *COMPONENTS §4.13; all roles.*
- **LL-31 · An unmarked gap looks exactly like a settled decision.** A design document that reads cleanly hides its own gaps. *Guard:* every open point is a **first-class inline marker** (`NOT DECIDED`, with who decides and a recommendation) at the point where the reader is standing — never a footnote, never silence. Silence must never read as decided. → *COMPONENTS §4.13; roles/lead.*
- **LL-32 · Two seats can read the same colour differently.** Status markers and severity markers share a palette; without one codified legend, a fresh clone infers meanings and mis-reads urgency. *Guard:* ONE symbol legend in the charter, one meaning per marker; a fresh clone **reads** the legend, never infers it. → *COMPONENTS §4.5.*
- **LL-33 · Start the canonical-doc discipline at FOUNDING, not mid-cycle.** The two-document rule was adopted mid-cycle, at the cost of a consolidation pass over a dozen drifted files. *Guard:* create the canonical doc + the log on day one, even when the design is thin — the discipline exists from the start or it starts with a repair bill. → *FOUNDATION-METHOD Phase 3.3.*

### Review & synthesis

- **LL-34 · The synthesiser's own summary is the least-audited artifact in the system.** The Lead compiled a multi-lens review; a separate audit of that synthesis caught real errors — including an **inverted finding direction** and a **dropped hard requirement**. Everyone audits the inputs; nobody audits the compilation. *Guard:* verify-don't-attest **includes your own synthesis** (re-derive each claim before relaying it), and a *different* seat audits any synthesis that feeds a decision. → *COMPONENTS §1.11 + §11; roles/lead + roles/ga.*
- **LL-35 · Review lenses must be blind-first and must state what they did NOT cover.** Independent perspectives converge (and inherit each other's blind spots) the moment they read each other; and a lens that only reports findings hides its own coverage gaps. *Guard:* each reviewer takes one lens over the whole artifact blind, cites exact numbered statements, and **lists what was not covered** — the uncovered list is a first-class output. → *COMPONENTS §11; roles/qa + roles/ga.*

### Orchestration

- **LL-36 · Session IDs rotate; a dispatch to a dead session is silently lost.** Role sessions get replaced (archived, re-cloned); a message or closure relayed to the *old* session simply vanishes — no error, no bounce. *Guard:* **verify the ACTIVE session** (list sessions; confirm the cwd is the live clone) before every dispatch; a spawn prompt only for a seat with no live session. → *COMPONENTS §8; roles/lead.*
- **LL-37 · Background/async subagents stall invisibly.** Work routed to invisible background agents failed silently, unobservable by the human. *Guard:* all research/background work runs in **visible role sessions** the Director can watch; every role agent completes its own task and spawns no subagents, so a stall is visible. → *COMPONENTS §4.9.*
- **LL-38 · Convergence is not confirmation — present, then WAIT.** Agreement reached in conversation was treated as a lock; the human had not actually confirmed. *Guard:* every lock (design, roster, scope, cost) is **presented and explicitly confirmed** before anything downstream builds on it; never tell a seat something is ruled that has not been ruled. → *FOUNDATION-METHOD Phase 1; roles/lead + roles/pm.*
- **LL-39 · Lead with the BEST answer, not the first safe one — and rigor is never excused by humility.** The coordinating seat twice had to be dragged by the human from an adequate recommendation to the right one; separately, thin analysis arrived dressed in careful hedging. *Guard:* work the full solution space and lead with the optimum (state the leaner option only where real dollars differ); disclaimers never substitute for analysis. Challenge with a recommendation, always. → *roles/lead + roles/architect + roles/pm.*

### Measurement & ground truth
*The deepest cluster: how a scoring/judging engine gets honestly measured. Generic to ANY system that scores, ranks, classifies or recommends.*

- **LL-40 · Internally consistent ≠ correct — certification and accuracy are different claims.** A ruleset was certified total, unambiguous and contradiction-free — **zero blocking findings — while its accuracy had never been tested against a ground truth from outside its author's own cases.** A ruleset encoding a wrong belief passes its own cases perfectly. *Guard:* state the two halves separately, always; close the accuracy half only with an **external, blind, write-once ground truth** labelled by a domain expert against a rubric agreed *first*. → *COMPONENTS §11; roles/aiq + roles/ai-ml.*
- **LL-41 · Freeze before you measure — and pin the COMMIT, because a validator can validate a stale one.** Measuring a moving ruleset makes the seal meaningless; separately, a validation pass nearly graded a commit that was no longer HEAD of the thing being shipped. *Guard:* freeze the ruleset at one **pinned commit hash**, seal the outputs at that hash before any label exists, and every validation record names the exact hash it validated. The freeze lifts only for the post-measurement recalibration it protected. → *COMPONENTS §11; roles/aiq.*
- **LL-42 · Same tier, wrong reason = coincidental agreement — grade the CATCH, not the verdict.** A tier-only grade passed a fix that reached the right answer for the wrong reason; the reason-level grade caught it (a SEV2: right tier, wrong catch). *Guard:* **catch-matching over tier-matching** — agreement on the verdict while disagreeing on *why* is a coincidence hiding a real defect; grade against a shared reason-vocabulary agreed before the run. → *COMPONENTS §1.12 + §11; roles/aiq.*
- **LL-43 · A same-set re-seal is fit-to-test — NEVER quote it as the accuracy number.** After recalibrating against a measured failure set, re-running on that same set "improved" the score — necessarily: the rules were tuned against exactly those cases. It confirms the fixes *fired*; it grades nothing. *Guard:* the honest number comes only from a **fresh draw the fix never saw**; label every same-set figure "fit-to-test" wherever it appears, and never let it travel without that label. → *COMPONENTS §11; roles/aiq + roles/lead.*
- **LL-44 · Pre-register predictions, write-once, BEFORE the run.** Expected failure lanes were written down (sealed) before a measurement run; when they landed, the confirmation was a *prediction* — not a post-hoc story. *Guard:* before any scored run, record write-once what you expect and where; a surprise must be visibly a surprise. → *COMPONENTS §11; roles/aiq.*
- **LL-45 · Design the fix on the PRINCIPLE, never tuned to flip the known failures.** A recalibration designed to flip the measured misses would overfit them — and a fresh draw exposes it. *Guard:* state the fix as a principle over the mechanism (what property of the world it encodes), validate it on that statement, and expect the fresh-draw grade to be the arbiter. → *roles/ai-ml.*
- **LL-46 · A fix that removes a masking error ships WITH the guard for what the mask hid.** Fixing a measurement bug *alone* flipped a coincidentally-correct refusal into a confident wrong positive — the bug had been masking a real hazard the system couldn't see. *Guard:* before shipping a fix that removes a mask, ask what the masked error was *accidentally protecting against*, and land the fix paired with an explicit guard for it. → *roles/ai-ml + roles/architect.*
- **LL-47 · Grader independence is fragile — contamination voids the run.** Multiple grading runs had to be voided for contamination (the grader had seen material it was supposed to be blind to). *Guard:* a genuinely independent grader is a **different model/seat, a fresh invocation, blind to the system's answers and to other graders**; audit the blindness before trusting the grade, and void on contact — a contaminated grade is worse than none. → *roles/aiq.*
- **LL-48 · A gate that cannot fail is worse than no gate — plant the negative control.** Quality review found multiple green legs that could not fail on the defect they claimed to guard (vacuous green). *Guard:* every leg is **armed** — proven to FAIL on a planted negative control — or it is an exit-visible SKIP; "green" from an unarmed leg manufactures false confidence. → *COMPONENTS §1.5 + §6; roles/qa + roles/devops.*
- **LL-49 · The boundary between "mechanically certified" and "human judgment" is itself a judgment — and the pressure always runs toward over-claiming the mechanical side.** The cure: a duty enters the certified column **only if a seat OTHER than the one judged can produce a reproducible negative control** — the one enforcing question is *"show me the input this green would reject."* No answer ⇒ the duty is HUMAN and escalates. Default HUMAN; certified is earned, never assumed. → *COMPONENTS §10; all roles.*
- **LL-50 · An oracle row must name the leg's ACTUAL assertion — the residue goes to HUMAN.** An audit of the certified column found rows claiming more than their legs actually asserted (the leg checked a proxy; the row claimed the property). *Guard:* every certified cell states **exactly what the leg asserts**, and everything the oracle cannot soundly check is named in the HUMAN column — an unnamed residue is a green certificate over real exposure. → *COMPONENTS §10; roles/ga.*
- **LL-51 · The defects were never invisible — they were UNWRITTEN. Check written claims mechanically, on every revision.** Four mechanical checks over authored decision-tables (exhaustive · reachable-under-stated-order · declarative-about-change · stage contracts) found defect after defect that careful expert reading had missed — and two of one round's defects were introduced by the previous round's own *correct* fixes. *Guard:* force the author to write the implicit claim down, check it mechanically, and **re-run on every revision** — a clean run proves nothing about the next one. When a new defect class appears, ask "what was the author allowed to leave unsaid?" → *COMPONENTS §11 spirit; roles/ai-ml + roles/qa.*
- **LL-52 · A number may only be compared when its basis is identical — and the basis must travel WITH the number.** Numbers computed on different bases (different axes measured, different maturity ages, fit-to-test vs fresh-draw) invite comparisons they cannot support, and the reader cannot see it. *Guard:* wherever a number is shown, state what it was computed from; where bases differ, fix the basis or refuse the comparison. Filling a missing value with a middling default to make arithmetic work is *assessing* it — absence is never a judgment. → *roles/all (a universal); COMPONENTS §1.6.*
- **LL-53 · Only testing what you believe in truncates the range — a null result becomes uninformative, permanently.** If predictions are recorded only for the candidates that get used, there is no variation in the predictor and no correlation can ever be computed — and it looks fine until someone tries to read it. *Guard:* design the comparison group in from the start (record the prediction for every scored candidate, used or not); state the asymmetry — a positive result understates, a null cannot distinguish "doesn't work" from "only sampled the top." → *roles/ai-ml + roles/data-eng.*

### Git & mechanics

- **LL-54 · A hot-file rebase conflict is almost always a pure append collision — keep BOTH, yours last.** On an append-only shared file (a working log, a board), concurrent pushes collide constantly; the resolution recurred ~10× in one session: keep both entries, yours last, remove the three conflict markers. Treating it as a real conflict (picking a side) silently deletes another seat's entry. → *COMPONENTS §3 hot-files; all roles.*
- **LL-55 · Anchor precision edits on a single clean line.** A multi-line anchor with an embedded line-break breaks the match silently in edit tooling; anchor on one distinctive line and expand from there. → *roles/all (mechanics).*

### The delivery pipeline (anti-churn)
*Harvested from a cycle where incomplete / inaccurate / conflated fragments reached the human one at a time, forcing quality-control instead of decisions (the human nearly abandoned the tool). The fix is a pipeline, not a patch.*

- **LL-56 · The decision-maker must DECIDE, never DEBUG — put a five-gate pipeline in front of them.** A full day was lost to the human doing quality-control on fragments arriving one at a time. *Guard:* nothing reaches the decision-maker until **COMPLETE · GROUNDED · RECONCILED · VERIFIED** — five gates (**SCOPE** one-axis → **GROUND** complete + every-number-flagged → **RECONCILE** by a second seat/GA, never the author → **VERIFY-AT-SOURCE** the Lead reads citations not claims → **DECIDE**). **If they catch an error instead of deciding, an earlier gate failed and the item goes back — never patched in front of them.** → *COMPONENTS §4.15 + §5; roles/lead; CLAUDE.md spine.*
- **LL-57 · Completeness by default — nothing under the rug; deferred ≠ excluded.** A cost table that silently excluded build-deferred scope flattered every margin until the human probed — and the pattern recurred across financials, scope and design. *Guard:* anything before a decision-maker shows the COMPLETE picture — deferred parts in **at full weight** (deferral is a schedule fact, not a reason to omit), every number flagged **measured/estimated/unmeasured**, dropped items surfaced **with their reason**, presented **proactively** (if they had to probe, it already failed). Accountability runs both ways. → *COMPONENTS §1.13; roles/lead + roles/ga.*
- **LL-58 · A consistency check passes a uniformly-wrong fact every time — cite the SOURCE, and the REVISION.** A fabricated scope string survived across four documents because every copy agreed; separately, edits were nearly applied to text that wasn't there (a plausible diff). *Guard:* external facts carry **source + read-date** or they are a GAP, re-verified at point of use; cite the exact **revision you observed against**. Agreement between copies is not evidence — only a source is. → *COMPONENTS §1.14; roles/all.*
- **LL-59 · A supersession not copied to EVERY place it lives leaves live contradictions — propagation completeness is the lever.** One incomplete propagation list left a single decision contradicting two separate surfaces at once; the pattern recurred across five domains in one sweep. *Guard:* a decision is not closed until every downstream doc it binds is **named in its row and updated in the same commit** (protocol 3); the **RECONCILE gate** (protocol 15) and the periodic **contradiction & gap sweep** (§5) catch what slips. → *COMPONENTS §4.3 + §4.15 + §5; roles/lead + roles/ga.*
- **LL-60 · Seats surface blockers MID-TASK, not just on completion.** A seat whose assigned method could not run (its measurement surface didn't exist) correctly refused to fabricate a number and messaged the Lead at once — the value was in surfacing the blocker immediately, not delivering a wrong result or sitting silent. *Guard:* the assigned seat messages the Lead **the moment** it hits a blocking question, ambiguity or issue — it never sits on a blocker or guesses past one (protocol 11). → *COMPONENTS §4.11 + §2 template; roles/all; CLAUDE.md spine.*

## §D · The second live-cycle harvest — LL-61 … LL-68
*From the same team's continued operation past the first harvest: a verification-and-validation maturity (everything carries the artifact that makes it checkable · a recurring independent-validation step aimed at the Lead's own output · an operational-readiness assurance register). Generic to any governed multi-agent team.*

- **LL-61 · Nothing leaves a seat without the artifact that makes it checkable — and store the FILTER, not the value.** A benchmark survived unexamined *because it agreed* with the seat that held it (*"I would have discarded one that contradicted me in seconds"*); separately, a stored count decayed as its artifact grew, and a qualified figure (`min(2%, $1)`) was reasoned from as its rounded worst case one step later, producing a wrong conclusion the real figure never supported. *Guard:* a COUNT carries its ROWS, a NUMBER its SOURCE, a DECISION its DOCUMENTS, a DESIGN STATEMENT its id; **store the filter that re-derives the count**, not the cached number; **carry a qualified figure as its expression** and re-derive at every step that USES it, not only where it is stated. The assertions that most need checking are the ones nobody is motivated to check. → *COMPONENTS §4.16; roles/all.*
- **LL-62 · A constraint a vendor VOLUNTEERS outweighs a capability it ADVERTISES.** A category's actual mechanism was settled not by three pages of marketing but by a vendor's stated privacy *limit* — a documented limit is what they had to build around; a claim is what they want you to believe. *Guard:* when a vendor won't state its method, read what it says it CANNOT or WILL NOT do; the limits are load-bearing, the claims are not (and citing the marketing page at-source does not fix it — the page IS the source). → *COMPONENTS §4.16; roles/all + roles/legal + roles/secops.*
- **LL-63 · When a statement and its governing artifact disagree, the GOVERNING ARTIFACT wins — the failure is misassigned authority, not insufficient checking.** A terse log parenthetical was treated as authoritative over the canonical doc it merely summarised, and a seat folded that wrong answer into a committed artifact — *having quoted the governing sentence itself one message earlier.* An answer that *resolves* your open question is exactly the one you have no incentive to test. *Guard:* the protocol binds what you **accept**, not only what you produce; establish which source GOVERNS before resolving a disagreement — a summary never outranks its source, and a wrong answer dressed in a seat's artifact travels on that seat's credibility. → *COMPONENTS §4.16; roles/all.*
- **LL-64 · The seat that reconciles everyone else was the one nobody reconciled — validate the Lead's own output.** The two errors of a cycle lived exactly there: a seat's tautology relayed as a finding, and a decision-maker-set gate recorded as cleared before it was ruled — the synthesiser/reconciler's own output had no independent check. *Guard:* a **critical** change (engine rule/number · propagating decision · cross-document invariant · spend-moving) gets an independent, different-agent validation before it is presented as reconciled — **including Lead-authored artifacts** — tiered so routine work gets self-check only (validating everything recreates the churn the delivery pipeline removes). GA confirms the validation actually ran. → *COMPONENTS §4.17 + §5; roles/lead + roles/ga + roles/aiq.*
- **LL-65 · One report per piece of work, at completion — convergence the decision-maker must WATCH is indistinguishable from churn they must ARBITRATE.** Three seats reported the same finding into the human's lap in parallel — each correct, each properly routed — and the aggregate was unreadable; the human stopped the session over it. The fix bound *who* reports but not *how often*, and four Lead↔seat rounds in an hour still read as a loop. *Guard:* the Lead **holds, consolidates, reconciles the seats against each other, and presents ONCE** — one report per piece of work, at completion, not per leg (sole exception: a genuine blocker). The failure is the COUNT of channels, not any one message; the Lead is the proximate cause when it relays each finding onward as it arrives. → *COMPONENTS §4.15; roles/lead.*
- **LL-66 · A hazard row without a test is not an entry — instrument the judgment you cannot yet test.** Rulings named hazards that had no way to prove they held; "we'll test it later" quietly became "we never can." *Guard:* every hazard-register row carries a **test identifier and the build fails without one**; a not-yet-testable row names what would make it testable · its trigger · what must be built NOW · who watches, and its default disposition is **INSTRUMENT IT** — make the judgment observable, or accept-and-watch it explicitly. "We cannot test this" is not an available answer; deferring a test is fine, deferring the instrumentation destroys it. → *COMPONENTS §9.B10; roles/ga + roles/qa + roles/architect.*
- **LL-67 · Superseded design is DELETED, not parked — and a normative fix re-authors, never patches.** A fully-worked superseded model, left bannered "retained for trace," is the confident, complete shape that gets implemented by whoever finds it first; separately, a defect-fix that inserted alongside the old text left a spec saying two contradictory things, and an implementer followed the stale half. *Guard:* delete superseded design from anywhere it can be built from (check what else rides in a row before cutting it — a live ruling inside a cut row goes with it); a normative-doc fix **re-authors** the sections it touches. A document that says two contradictory things is worse than one that is simply wrong. → *COMPONENTS §4.19 + §5; roles/lead + roles/architect.*
- **LL-68 · A decision states its scope — instance or class — at the moment it is ruled.** Two ruled rules were re-derived from scratch days apart because neither said whether it governed one instance or the whole class; a rule filed under one instance reads as complete, so the register cannot catch the omission. *Guard:* the ruling itself declares instance-or-class when it is made. → *COMPONENTS §4.18; roles/lead + roles/architect.*

## §E · Founding #5 — HELM (`trade`), an AI/finance SaaS — LL-69 … LL-71
*A greenfield founding where the Director skipped the Script-1 human checkpoint, the harness refused an active permissions file, and gh was unavailable. Each genericised.*

- **LL-69 · Script 2 can arrive without Script 1's answers — author `PROJECT-CONFIG.md` from the recommended defaults FIRST, never block.** The human checkpoint between the two scripts is skippable: the Director pasted Script 2 with no `PROJECT-CONFIG.md` present, yet every Script-2 step opens by reading it. *Guard:* SCRIPT-2 STEP 0 authors `PROJECT-CONFIG.md` as its **first action whenever the file is absent**, filling every value from the Lead's recommended default recorded **DIRECTOR-PENDING** (LL-24), and holding the genuine LOCKS (roster · cost model) and the product paragraph for explicit confirmation (LL-38).
